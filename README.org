#+title: cl-llm-provider-api

Portable Common Lisp protocols and value types for language-model providers and
bounded inference inputs.

The library defines semantic provider events and results, concrete wire clients,
context assembly, structured-output contracts, shared inference budgets, read-only
views, content-addressed context objects, and a layered provider registry with
model discovery. Applications own credential stores, cache storage, prompt
policy, conversation projection, and tool dispatch.

* Systems and package

- ASDF system: =cl-llm-provider-api=
- Optional concrete protocols: =cl-llm-provider-api/wire=
- Optional HTTP condition adapter: =cl-llm-provider-api/dexador=
- Optional provider registry: =cl-llm-provider-api/registry=
- Test system: =cl-llm-provider-api/tests=
- Package: =CL-LLM-PROVIDER-API=
- Nickname: =LLM-PROVIDER-API=

Install the locked dependencies and run all tests:

#+begin_src sh
./script/bootstrap
./script/check
#+end_src

* Projected requests and execution

Load =cl-llm-provider-api/wire= for Responses, Chat Completions, Anthropic
Messages, and Gemini GenerateContent encoding and stream assembly. Use hash tables for JSON objects, vectors
for arrays, and portable Responses-shaped transcript items. Subclass the existing
provider classes to specialize wire naming, instruction placement, and provider
metadata without introducing application objects into the wire layer.

Construct =WIRE-REQUEST= with =:model=, =:items=, =:prefix=, =:suffix=, and an
=:options= property list. Supply already-projected history and instruction texts.
Call =PROVIDER-REQUEST-OBJECT= with a provider, the projection, and tool vector.
Responses accepts namespace declarations; Chat Completions and Messages accept
encoded tools. Use =PROVIDER-WIRE-TOOLS= for protocol-specific tool projection.

Shared options include =:maximum-output-tokens=. Responses additionally accepts
=:reasoning-effort=, =:reasoning-summary=, and =:fields= (alternating wire keys and
values). Chat accepts =:stream-usage-p=, =:reasoning-parameter=,
=:reasoning-effort=, and =:output-ceiling-field=. Messages accepts =:cache-p= and
=:ephemeral-items= for separately projected volatile history.

Messages projects root =oneOf=, =allOf=, and =anyOf= tool-schema constraints into
an =input_schema.description= annotation because Anthropic rejects those keywords
at the root. Nested composition, properties, and unconditional requirements are
preserved. Validate returned arguments against the original schema in your tool
dispatcher; the wire schema is a less restrictive projection.

Call =PROVIDER-EXECUTE-REQUEST= with =:transport=, =:event-callback=, and optional
=:secrets=, =:cleanup=, =:call-with-deadline=, and =:completion= hooks. The transport
accepts the request object and returns a stream, HTTP status, and response headers.
The library normalizes HTTP and terminal failures and redacts supplied secrets
from detached headers, events, results, and diagnostics. Use =:cleanup= to dispose
of each acquired stream; the default abort-closes it. Cleanup is best effort:
its errors and deadline failures do not replace the request outcome. Completion
runs after valid terminal consumption and cleanup.

Load =cl-llm-provider-api/dexador= and wrap the request thunk with
=PROVIDER--CALL-WITH-TRANSPORT-NORMALIZATION= to classify socket, TLS, and deadline
conditions from transport opening and SSE line reads. Application callbacks run
outside that classifier. Pass =:terminal-errors-p t= only when wrapping a transport
opening directly. Convert Dexador HTTP conditions with =PROVIDER-SIGNAL-HTTP-FAILURE=.
Supply credentials and authenticated request headers from the application.
Resampling and transient retries use separate budgets in =CALL-WITH-BOUNDED-RETRIES=.
Supply =:maximum-retries=, =:delay-function= (retry number and condition), and
=:call-with-attempt= for a custom delay policy or attempt scope.

* Context assembly and output contracts

Create bounded =CONTEXT-CONTRIBUTION= values with =MAKE-CONTEXT-CONTRIBUTION=.
Use =MAKE-CONTEXT-RESOLVER= and =CONTEXT-RESOLVE= to select contributions by
lifetime, supersession, deduplication, conflict group, mandatory class, priority,
and available budget. A =CONTEXT-SELECTION= includes selected and omitted values.
Call =CONTEXT-SELECTION-COMPLETE= only after a successful request to acknowledge
successful-delivery lifetimes. Applications supply request identity, token costs,
rendering, and evidence trust boundaries.

Use =OUTPUT-SCHEMA-NORMALIZE= for the supported native schema subset and
=OUTPUT-SCHEMA->JSON= for its JSON representation. Validate values with
=OUTPUT-SCHEMA-VALID-P=. Decode exact JSON through =OUTPUT-JSON-DECODE= and
convert portable tagged values through =OUTPUT-JSON->SEXP= and
=OUTPUT-SEXP->JSON=. Object properties and required keys, arrays, scalar JSON
types, enums, alternatives, and additional-property constraints are supported.
Invalid contracts and values signal =OUTPUT-CONTRACT-ERROR= and
=OUTPUT-VALUE-ERROR= with field diagnostics.

=OUTPUT-TEXT-ANSWER= reads a model's free-text answer against a schema: it finds
one JSON value in the text, tolerating prose and code fences around an object or
array, validates it, and returns the tagged value, whether it was valid, and
otherwise a sentence asking the model to repair the answer. =OUTPUT-TEXT-JSON=
is the extraction alone. =OUTPUT-JSON-SCHEMA->SCHEMA= imports a JSON Schema
object into the native subset, the reverse of =OUTPUT-SCHEMA->JSON=.

* Provider values

All values are ordinary CLOS instances created with =MAKE-INSTANCE=.

- =PROVIDER-EVENT= is the root event class.
- =ASSISTANT-DELTA-EVENT= and =REASONING-DELTA-EVENT= carry streamed text.
- =PROVIDER-ITEM-EVENT= carries one completed provider-native item.
- =PROVIDER-COMPLETED-EVENT= carries response identity, usage, and turn state.
- =PROVIDER-RETRY-EVENT= carries bounded reconnect metadata.
- =PROVIDER-RESULT= carries ordered output items, tool calls, usage, routing
  state, and =:CONTINUE=, =:END=, or =:UNSPECIFIED= turn completion.

#+begin_src lisp
(make-instance 'llm-provider-api:provider-result
               :response-id "response-1"
               :output-items (list message)
               :tool-calls calls
               :usage '(:total-tokens 42)
               :turn-completion :end)
#+end_src

Output items and usage metadata deliberately have type =T=. A provider may use
hash tables, association lists, structures, or application-specific objects.

* Provider protocol

Subclass =MODEL-PROVIDER= and implement =PROVIDER-STREAM-TURN=. The callback
receives semantic =PROVIDER-EVENT= instances and the method returns one
=PROVIDER-RESULT=.

#+begin_src lisp
(defclass example-provider (llm-provider-api:model-provider) ())

(defmethod llm-provider-api:provider-stream-turn
    ((provider example-provider) conversation
     &key tool-namespaces event-callback goal-context compaction-p)
  (declare (ignore provider tool-namespaces goal-context compaction-p))
  (funcall event-callback
           (make-instance 'llm-provider-api:assistant-delta-event
                          :text "hello"))
  (make-instance 'llm-provider-api:provider-result
                 :output-items (list conversation)
                 :turn-completion :end))
#+end_src

The portable provider protocol also exposes:

- =PROVIDER-FAMILY=
- =PROVIDER-WITH-CONFIGURATION=
- =PROVIDER-CONSUME-STREAM=
- =PROVIDER-NATIVE-COMPACT-CONVERSATION=
- =PROVIDER-SET-REASONING-SUMMARIES=
- =PROVIDER-OUTPUT-CEILING-P=
- =PROVIDER-NORMALIZE-OUTPUT-ITEM=

Conservative defaults return =:CUSTOM=, =NIL=, the unchanged provider, or the
unchanged item where a safe default exists.

* Wire protocol

=RESPONSES-API-PROVIDER= and =CHAT-COMPLETIONS-PROVIDER= identify common wire
families. =PROVIDER-WIRE-PROTOCOL= returns =:RESPONSES-API=,
=:CHAT-COMPLETIONS=, or =:CUSTOM=.

Request implementations can specialize:

- =PROVIDER-WIRE-TOOL-NAME=, =PROVIDER-WIRE-TOOL=, and =PROVIDER-WIRE-TOOLS=
- =PROVIDER-WIRE-INPUT-ITEM=
- =PROVIDER-RESPONSES-WIRE-EFFORT=
- =PROVIDER-RESPONSES-REASONING-SUMMARY=
- =PROVIDER-RESPONSES-HOSTED-TOOLS=
- =PROVIDER-RESPONSES-INSTRUCTIONS-PLACEMENT=
- =PROVIDER-RESPONSES-REQUEST-NAMESPACES=
- =PROVIDER-RESPONSES-REQUEST-FIELDS=
- =PROVIDER-REQUEST-OBJECT=

The Responses API default joins a namespace and tool name with a dot. Wire
objects remain application-defined values, so the library does not impose a
JSON representation. Responses instructions use conversation input items by
default. Providers may return =:TOP-LEVEL= from
=PROVIDER-RESPONSES-INSTRUCTIONS-PLACEMENT= to use a top-level =instructions=
request field instead.

** Deferred namespaces and tool search

=PROVIDER-DEFERRED-WIRE-TOOLS= declares every namespace with
=defer_loading= functions and adds one client-executed =tool_search= tool
(=PROVIDER-TOOL-SEARCH-TOOL=, with a host description). When the model answers
with a call, =PROVIDER-TOOL-SEARCH-CALL-P= recognizes it and
=PROVIDER-TOOL-SEARCH-OUTPUT= answers it from the offered namespaces: terms
from the query score exact tool names over name fragments, namespace names and
description words, a term naming a namespace exposes all of it, and at most
=*PROVIDER-TOOL-SEARCH-DEFAULT-LIMIT*= other tools are returned.
=PROVIDER-TOOL-SEARCH-OUTPUT-REPLAY= rebuilds a stored output for the next
request, or replays it empty with =:TRIMMING-P= for compaction.

** Gemini GenerateContent

=GEMINI-GENERATE-CONTENT-PROVIDER= encodes a projected request as
GenerateContent: prefix texts become the =systemInstruction=, history items
become =contents= (calls with decoded =args=, results as =functionResponse=
named after their call, reasoning as thought parts, images as inline base64
data), and suffix texts trail as one user content. =:MAXIMUM-OUTPUT-TOKENS=
and =:INCLUDE-THOUGHTS-P= fill =generationConfig=. The SSE consumer streams
thought and answer text, decodes namespaced calls, maps usage, completes on
=STOP=, and signals an incomplete response for =MAX_TOKENS=. A host that wraps
each response in an envelope specializes =PROVIDER-GEMINI-STREAM-RESPONSE=.

** GitHub Copilot wire helpers

Use =COPILOT-MODEL-CATALOG= to decode tool-capable account models into plists
with =:NAME=, =:PROTOCOL=, =:DESCRIPTION=, =:REASONING-EFFORTS=, and optional
=:CONTEXT-WINDOW=. Supply =:MODEL-PREFIX= for a host namespace and
=:PERSONAL-ACCOUNT-P= for the individual-account policy fallback. During
explicit login, an optional =:ENABLE-MODEL-FUNCTION= receives each eligible
unconfigured model ID and returns true after enabling it.

=COPILOT-MODEL-PROTOCOL= selects Chat Completions, Responses, or Messages.
Use =COPILOT-PROTOCOL-ENDPOINT= for the corresponding path,
=COPILOT-BASE-URL= for the token's trusted proxy host, and
=COPILOT-HTTP-HEADERS= for catalog requests. For streaming, pass the selected
=:PROTOCOL= and =:INITIATOR= to =COPILOT-STREAM-HEADERS=; image blocks require
an additional vision header. Malformed catalogs, untrusted hosts, and unknown
protocols signal =PROVIDER-ERROR=. Implement device login, credential storage,
and account policy HTTP requests in the host application.

* Stream engine

=READ-SSE-DATA= decodes one server-sent event's joined data field from a
character stream. Lines and events are bounded by
=*SSE-MAXIMUM-LINE-CHARACTERS*= and =*SSE-MAXIMUM-EVENT-CHARACTERS*=;
violations signal the class named by =*STREAM-LIMIT-ERROR-CLASS*=,
=PROVIDER-STREAM-LIMIT-ERROR= by default. A drained stream returns
=*SSE-END-OF-STREAM*=. Hosts needing runtime-specific inactivity deadlines
install a wrapper as =*SSE-READ-LINE-FUNCTION*=; =cl-llm-provider-api/dexador=
provides =SSE-READ-LINE-WITHIN-INACTIVITY-DEADLINE=, which fails a line that
stalls past =*SSE-INACTIVITY-SECONDS*= with a retryable
=RESPONSE-STREAM-ERROR=, because Dexador's read timeout does not cover the
blocking reads of a TLS stream.

=READ-CHARACTER-SEQUENCE= fills a string like =READ-SEQUENCE= using requests
no larger than =*CHARACTER-READ-SEQUENCE-WINDOW*=, staying on the portable
buffered path on runtimes whose large decoded reads misbehave.

=CALL-WITH-BOUNDED-RETRIES= retries an attempt function over the
=*BOUNDED-RETRY-DELAYS*= backoff schedule when it signals
=PROVIDER-RETRYABLE-ERROR=, reports each wait through =PROVIDER-RETRY-EVENT=
callbacks, and restarts immediately on =PROVIDER-RESAMPLE-REQUESTED=. Hosts
bridge their own condition types by inheriting from these classes.

=CALL-WITH-STREAMING-RETRIES= builds on it for streamed requests. Each attempt
streams through the callback it is handed, so the engine sees whether reasoning,
text or an item arrived before a failure. Failures before any output retry up to
=*PROVIDER-MAXIMUM-TRANSIENT-RETRIES*= times; once output has streamed, every
retry bills a fresh generation, so only =*PROVIDER-MAXIMUM-STREAMING-RETRIES*=
are allowed before the request ends with =PROVIDER-STREAM-ABANDONED=. Every
failed attempt is reported as a =PROVIDER-ATTEMPT-FAILED-EVENT= audit record,
and waits come from =PROVIDER-JITTERED-RETRY-DELAY=: a doubling base capped at
32 seconds with twenty percent jitter.

=CALL-WITH-CREDENTIAL-REFRESH= retries an attempt once with a forced
credential refresh after =PROVIDER-UNAUTHORIZED=, when the credentials are
refreshable, and hands a final rejection to a host function that signals the
host's own authentication condition.

* Bounded inference

** Budgets

=RLM-BUDGET-CREATE= creates a subtree budget with shared call and token counters
and frame-local recursion depth. =RLM-BUDGET-ACQUIRE-REQUEST= atomically reserves
one call and a bounded output tranche. Settle it with
=RLM-BUDGET-SETTLE-OUTPUT=, passing =RLM-USAGE-BILLABLE-TOKENS= of the reported
usage so prompt-cache reads do not drain the pool. Descendants created by =RLM-BUDGET-DESCEND= share the
same counters.

#+begin_src lisp
(let* ((budget (llm-provider-api:rlm-budget-create
                :calls 8 :tokens 80000 :depth 2))
       (tranche (llm-provider-api:rlm-budget-acquire-request budget)))
  (unwind-protect
       (call-provider :maximum-output-tokens tranche)
    (llm-provider-api:rlm-budget-settle-output budget tranche usage-total)))
#+end_src

Exhaustion signals =RLM-BUDGET-EXHAUSTED= with a =:CALLS=, =:TOKENS=, or
=:DEPTH= dimension and an optional task label.

** Views

=RLM-VIEW-MATERIALIZE= accepts a string, pathname, =RLM-VIEW=, or a plist with
=:CONTENT= or =:PATH= and an optional =:LABEL=. =RLM-VIEWS-MATERIALIZE= numbers
duplicate labels. =RLM-VIEWS-RENDER= emits digest-delimited read-only blocks.

** Context objects

=RLM-CONTEXT-STORE-CREATE= opens a directory-backed content-addressed store.
=RLM-CONTEXT-INTERN= and =RLM-CONTEXT-INTERN-PATHNAME= publish UTF-8 content
atomically under its SHA-256 digest. Reads and lookups verify the digest and
signal =RLM-VIEW-ERROR= if stored content is corrupt. Store roots are
canonical absolute directories. Object reads reject noncanonical cache paths,
and passing an object to another store re-interns its verified content there.

#+begin_src lisp
(let* ((store (llm-provider-api:rlm-context-store-create #P"context/"))
       (object (llm-provider-api:rlm-context-intern
                store "large immutable input" :label "corpus")))
  (values (llm-provider-api:rlm-context-object-digest object)
          (llm-provider-api:rlm-context-object-content object)))
#+end_src

* Provider registry

=cl-llm-provider-api/registry= keeps provider registrations in ordered source
layers. =provider-registry-create= names the layers from lowest to highest
precedence, the defaults for models that declare no context window or reasoning
efforts, and three optional host hooks: functions reading and writing the
portable model cache form for a context, and a function told whenever the
effective models may have changed.

=provider-registry-register= adds or replaces one name in one source. A name
resolves to its highest source, and a later registration wins within one source,
which =provider-registry-registrations=, =provider-registry-find= and
=provider-registry-for-model= report. A registration's :MODEL-DISCOVERY function
receives the context passed to =provider-registry-refresh-models=; discovered
models follow the declared ones, a declared model gains a discovered context
window only when it declares none, and refreshes of one provider never overlap.
A failed refresh keeps the previous models and is returned as a
=provider-model-discovery-error= instead of signaled.
=provider-registry-load-model-cache= adopts cached models whose provider and
discovery endpoint still match, and =provider-registry-snapshot= and
=provider-registry-restore= undo registry changes exactly. Invalid input signals
=*provider-registry-error-class*=, =provider-registry-error= unless a host names a
subclass.

=cl-llm-provider-api/wire= adds =model-list-decode=, which turns an
OpenAI-compatible =/models= response into registry model specifications, reading
the context window from whichever of the common field names a catalog uses.

#+begin_src lisp
(let ((registry (llm-provider-api:provider-registry-create)))
  (llm-provider-api:provider-registry-register
   registry "example"
   :models '((:name "example-large" :context-window 200000))
   :factory (lambda (&rest arguments) (make-example-provider arguments))
   :source :builtin)
  (llm-provider-api:provider-registry-model registry "example-large"))
#+end_src

* Tool and schema helpers

The exported tool helpers provide provider-safe names, JSON Schema builders,
required-argument diagnostics, conservative placeholders, and ordered
namespace grouping without depending on application registry classes.
=PROVIDER-TOOL-IDENTIFIER-MAP= sanitizes UTF-8 raw names and appends a stable
FNV-1a suffix within the 23-character Chat Completions budget.  It signals
specific duplicate, limit, and collision conditions.  Use
=PROVIDER-ARRAY-SCHEMA= and =PROVIDER-ENUM-SCHEMA= for reusable schema shapes;
their optional descriptions are omitted when =NIL=.

* Automatic Copilot model selection

Encode =COPILOT-AUTO-SESSION-REQUEST='s JSON object and POST it to
=/models/session=. Pass the session response and raw =/models= catalog to
=COPILOT-AUTO-SESSION-MODEL=; it returns a concrete model spec and session token.
Send =Copilot-Session-Token= with the concrete request using that model's protocol.
Keep the token within the request's credential scope and include it in redaction.
Use =:include-auto-p t= with =COPILOT-MODEL-CATALOG= to expose =auto= in a picker.
